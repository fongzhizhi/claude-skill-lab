# ones-parser 设计文档

## 目标

公司所有开发事宜（需求、缺陷、任务等）在 ONES 项目管理平台登记，对话中高频出现 ONES 复制出来的单内容。本技能将"解析 ONES 复制内容"这一领域知识固化为单一事实来源：识别工单 ID、类型、标题、链接，输出稳定结构，供 commit-draft 等模块消费。

## 设计原则

- **链接是唯一可信锚点**：ONES 链接 hash 末尾的工单 ID（`PRO-156328`、`WIKI-2048`）是权威标识；标题是展示文本，可能被用户手改或截断。冲突时以链接为准。
- **纯文本，零外部依赖**：解析只基于用户粘贴的文本。不调用 ONES API、不访问链接——既是部署零依赖（无 `meta.json`），也避免编造链接之外的信息。
- **容忍变体**：实际粘贴格式与"模板"不一致（用户描述的模板是两行，实际常为单行、多空格）。解析规则覆盖单行 / 两行 / Markdown 链接 / 多单混排等形态。
- **单一事实来源，供多方复用**：Claude Code 的 skill 之间不能互相"调用"，通过可复制的"引用片段"让其他模块（如 commit-draft）嵌入同一套解析规则，避免规则漂移。
- **不编造**：解析不到标题则留空说明；未知 ID 前缀标"类型未知"，不臆测。

## 关键设计决策

1. **不分析单类型**：ONES 的 ID 前缀（PRO/WIKI/TASK 等）无法可靠区分单是需求、缺陷还是其他类型，解析结果不输出类型字段，避免误导下游。
2. **冗余 team id 识别**：链接中 `<TeamId>`（如 `Tkdsads78`）是 base62 团队标识，容易被误认为单号，规则明确忽略。
3. **输出两级协议**：结构化结果（对话展示）与紧凑引用格式（commit footer / 文档引用），分别面向人读与机器消费。
4. **不发起网络请求**：为 ONES Open API 预留扩展空间——未来若接入 API 拉取真实标题/状态，是独立 skill 的自然演进，不改变本技能文本解析的定位。

## 边界

- 不解析 ONES 之外的链接。
- 不分析单类型（ONES ID 前缀无法可靠区分需求/缺陷等），不输出类型字段。
- 不处理乱码（解析结果保留原文标题字面，含乱码时交由使用方处理）。
- 多单混排时逐个解析，不合并语义。

## 变更理由

- **v0.1.2**：同步 commit-draft 的 footer 引用格式——`Refs:` 只输出纯链接，单 ID 由 `Title:` 行体现，避免重复。
- **v0.1.1**：去掉单类型分析。用户实测发现 ONES ID 前缀无法可靠区分单是需求还是缺陷，类型字段会误导下游；标题提取不受影响。
- **v0.1.0**：初始设计。基于用户提供的两个真实粘贴样例（PRO 需求单、WIKI 文档单）与通用模板，归纳出单行 / 两行 / Markdown 链接三类变体及解析规则；设计"引用片段"机制供 commit-draft 等下游模块复用。
