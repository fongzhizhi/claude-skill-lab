# month-log-summary

> 为 month-log 月工作日志补写「AI月总结」章节：脚本算数据，AI 组织叙述。

month-log 的脚本总结是纯数据表格（工时/占比/环比/未完成任务），缺少公司月总结汇报需要的主观叙述。本 skill 阅读月总结数据、月计划与任务记录，在文档末尾补写一段先数据后结论的「AI月总结」，形成"人工记录 + 脚本统计 + AI 总结"三合一的月报。章节已存在时直接整体覆盖——数据更新、更换模型后随时重新生成即可。

## 功能 / 内容

- **单向生成**：读文档 → 生成叙述 → 写回文档末尾 `## AI月总结` 章节，不向用户索要额外素材
- **三种指定方式**：显式路径（先校验再执行）→ 只给月份（自动定位仓库）→ 什么都不给（默认当月，今天所在周的归属月，与 month-log `init` 一致）
- **仓库自动定位**：通过全局 `month-log` 命令（npm link）反查仓库真实路径，`logs/YYYY/YYYY-MM.md` 即月报告目录
- **覆盖即最新**：章节已存在则整体替换，不保留历史版本（git 有历史）
- **数据纪律**：所有数字取自月总结表格与任务行，先数据后结论，实事求是、不讲虚的
- **零侵入**：只写 SCRIPT 区之外的章节，`node index.js update/clear/watch` 均不受影响

## 前置依赖

无外部 CLI 依赖（定位仓库依赖 month-log 的 `npm run link` 全局命令，未注册时降级为询问路径）

## 部署

```bash
lab deploy month-log-summary
```

部署落点：`~/.claude/skills/month-log-summary/`

## 使用

对话中直接说，三种方式任选：

**方式 A：显式路径**（先校验存在与格式，再执行总结）

> 给 D:\MyWorking\github\month-log\logs\2026\2026-08.md 生成 AI 月总结

**方式 B：只给月份**（自动定位仓库）

> 总结上个月 / 给 7 月的月报补个 AI 月总结

**方式 C：什么都不给**（默认当月，按今天所在周的归属月）

> 生成 AI 月总结

仓库已定位但找不到目标月文档时，skill 会告知缺哪个文件并让你核实或提供路径，不自动创建。每次生成完成后会汇报文档路径、生成/覆盖状态与摘要，方便验收。生成的章节保持在文档末尾——其后如有手写内容，再次生成会被整体覆盖。
