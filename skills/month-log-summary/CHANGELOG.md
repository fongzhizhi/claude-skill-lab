# CHANGELOG

## v0.3.0 (2026-11-06)

- **输出结构改为 OKR 月报三段式**：`### 一、平时表现`（节奏 + 协同投入）、`### 二、常规工作`（任务总数 + 各类型数量/工时/占比 + 关键结果）、`### 三、自我评价`（数据肯定 + 问题复盘 + 下月行动），标题与顺序固定，可直接整段复制
- **新增数据口径**：周均 = 总工时 ÷ 有记录周数；任务总数/已完成数/未完成数取月表与「未完成任务」看板；主要类型可补单周峰值
- **素材范围扩展**：周总结从可选变为「平时表现」的必需数据源；任务行 `预估工时` 纳入预估偏差分析（无预估字段时不得声称"耗时超预估"）
- **版本号统一**：frontmatter 由滞后的 0.2.0 更新为 0.3.0，与 CHANGELOG 对齐

## v0.2.1 (2026-08-31)

- 撰写规则细化：总结改为**分节式格式**——开篇一句总览 + 2~4 个加粗小节标题（`**需求开发**（31.5h，占45.7%）`式，节头带数据）的分节叙述 + `**总体评价**：` 结尾节，每节 1~2 句短段、节间空行分隔，替代原来单个长段落
- 数据纪律、实事求是、主观性上限等规则不变

## v0.2.0 (2026-08-31)

- 模块更名：`ai-month-summary` → `month-log-summary`（v0.1.0 未部署即废弃，见下）
- **新增仓库自动定位**：通过全局 `month-log` 命令（npm link）反查仓库真实路径，目标文档 = `<仓库>/logs/YYYY/YYYY-MM.md`；未 link 时降级为询问路径
- **新增目标文档三种指定方式**：显式路径（先校验再执行）/ 只给月份（当月、上月、YYYY-MM）/ 什么都不给（默认今天所在周的归属月，与 month-log init 的跨月周归属一致，内置 node 计算命令）
- **移除案例原文**：不再内嵌 6 月/7 月历史汇报全文（个人非标准案例会被当样板照搬），改为提炼的撰写规则 + 中性结构模板（篇幅、先数据后结论、小类型合并处理）
- **结束汇报**：完成后明确告知文档路径、生成/覆盖状态、一句话摘要，提示验收并可要求重写

## v0.1.0 (2026-08-31)

- 初始版本（名 `ai-month-summary`，未部署即更名重构，不保留）
- 核心：阅读 month-log 月日志，在文档末尾生成/覆盖「AI月总结」章节
