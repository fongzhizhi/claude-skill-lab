# live-debugger

> 埋点数据驱动的前端 bug 排查：快速定位数据流转关键节点 → console.log 埋点 → 浏览器自动复现（Playwright MCP 优先，受阻降级人工）→ 读取 console 数据 → 收敛闭环直至修复。

前端定位 bug 最快最准的方式是 debugger——看调用栈判断流程是否符合预期，看数据判断状态是否符合预期。本技能把这个人工过程自动化：结合浏览器 MCP（playwright 等），重复执行"埋点 → 复现 → 看数据 → 收敛"循环，一步步缩小范围直到根因，修完后自动清除埋点并输出根因与修复方案报告。复现环节由 AI 通过浏览器自动执行，只有自动复现受阻（登录态/验证码/复杂操作）时才降级请求人工。

核心哲学：**埋点数据是主要信息来源，代码分析只服务于选埋点位置**（禁止深度分析）；**复现是每轮必做的验证动作**（AI 自动优先、受阻显式降级，不静默跳过）；**AI 自动复现通过 ≠ 修复完成**（收尾前由用户亲自确认）。

## 功能 / 内容

- bug 三要素前置：复现步骤、现状（问题）、预期——缺哪项问哪项，"预期"是收敛基准
- AI 自动复现：snapshot 看页面 → 按 ref 确定性操作（Playwright MCP 最佳），简单步骤免人工
- 受阻降级链：步骤缺失 → AI 推断最简路径尝试；自动化覆盖不了 → 请求用户描述或交回人工复现
- 埋点格式 `console.log('[live-debugger][<context>]', { vars })`，支持精确过滤与清除

## 前置依赖

| 依赖 | 说明 |
| --- | --- |
| 浏览器控制 MCP（软依赖） | playwright（推荐：无障碍快照省 token、ref 确定性交互）/ chrome-devtools / puppeteer 任一，用于打开/刷新页面、自动复现操作、读取 console。缺失时显式告知并询问（配置 or 降级手动复现），不静默降级 |

## 使用

- **自动触发**：对话中出现前端 bug 描述，要求"定位/调试/排查/修复"问题时使用。
- **手动调用**：`/live-debugger`，附上 bug 三要素：复现步骤（含测试环境与操作序列）、现状（问题）、预期（可选 URL）。

核心约定：

- 前置三要素：复现步骤、现状、预期缺一不可；复现步骤描述质量决定 AI 能否自动复现
- 埋点统一使用 `console.log('[live-debugger][<context>]', { vars })` 前缀格式，方便识别、过滤与精确清除
- 硬性限额：每轮排查 Read ≤ 3 / Grep ≤ 5，禁止通读文件/深挖调用链——代码分析只服务于选埋点位置
- 编译不等待：最多检查一次编译输出 mtime，严禁反复检查与 sleep 等待，编译是否生效由埋点数据出现与否验证
- 复现 AI 自动优先：简单步骤自动执行；受阻（尝试 2 次未触达/自动化覆盖不了）明确告知并降级人工，不静默跳过
- AI 自动复现通过 ≠ 修复完成：收尾前请用户亲自走一遍复现步骤确认
- tab 复用：navigate 优先复用已有空白 tab，不另开新 tab；若实现导致新开 tab，导航后关闭多余空白 tab，只保留目标页面一个 tab
- 默认页面 URL：`http://localhost/editor?cll=debug`（用户提供时优先；未提供直接打开默认地址并告知用户，不询问、不阻塞）
- 收尾自动清除全部埋点、保留修复代码，输出根因 + 修复方案报告

示例：`/live-debugger "编辑器里上传图片后缩略图不显示，点完上传按钮就没有反应"` → 确认三要素 → 快速定位埋点位置 → 埋点 → 打开/刷新页面 → AI 自动复现（或降级人工）→ 读取数据 → 收敛闭环至修复 → 用户最终确认。
