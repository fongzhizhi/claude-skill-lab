# feedback

## 反馈记录

### 2026-08-18（实测两次）

用户实测两次调用后的反馈：

1. **流程分析耗时过长**：技能重点应是"根据埋点分析问题"，却花费大量时间在分析代码上
2. **编译等待耗时过长**：检查编译是否完成很久，10s 的限制对 AI 没有时间约束力
3. **未打开浏览器**：两次调用都没有打开浏览器，最基本的验证操作未执行

→ 已修复（v0.1.1）：核心哲学前置（埋点数据驱动、代码分析只辅助）、限额收紧（Read ≤ 3 / Grep ≤ 5）并禁止深度分析、编译等待改为"不等待用数据验证"、浏览器验证强制化（每轮必做，找不到 MCP 工具必须明确告知并询问，禁止静默降级）。

### 2026-08-19（实测）

用户未提供页面地址时，技能没有打开默认地址。

→ 已修复（v0.1.2）：根因是 SKILL.md 文案歧义——"（未提供用默认值）"与加粗"缺失则先询问"在同一句并存，模型跟随了更强的"询问"分支。现把 URL 明确划为可选项并写死行为：未提供 → 直接打开默认地址并告知用户，不询问、不阻塞。

### 2026-08-21（实测）

打开浏览器空白页后，再打开指定或默认 URL，空白页不会被自动关闭——期望是"直接在空白页上打开链接"或导航后空白页自动清理。

→ 已修复（v0.1.3）：根因是 SKILL.md 未规定浏览器 tab 的复用与清理策略，navigate 行为随各 MCP 实现而异（chrome-devtools 在当前活动 tab 导航，playwright 在当前 page 或新建），可能出现"另开 tab 导航、空白 tab 残留"。现规定：导航优先复用已有空白 tab，不另开新 tab；若实现导致新开 tab，导航后检查 tab 列表并关闭多余空白 tab，保证只保留目标页面一个 tab。
