# feedback

## 初始创建 (2026-08-13)

- 需求来源：keeper 补齐方向（README 规划中）。三份指南已就位（ts-error-handling-guide 等），参考 comment-keeper / test-keeper 的做法创建执行技能，补齐 ts-standards 5 条规则的执行闭环。
- 决策：
  - 采用 Skill（依赖长文档 + 多分支流程）
  - 模块名 `error-handling-keeper`，与 keeper 家族命名对称
  - 两轨判定：语义等价改动直接做、控制流改动只列清单——错误处理是所有治理维度中行为风险最高的，任何改变程序行为的改动都不直接做
  - 交付核心是"控制流改动清单"（现状 + 建议处理方式 + 影响面），落地由用户决定
- 待实测确认项：语义等价判定的边界（throw 实例化时调用方错误类型依赖的核对是否够用）、控制流清单的粒度（是否会太多导致决策负担）、与 type-keeper 在"边界校验 + Zod"上的分工衔接。
