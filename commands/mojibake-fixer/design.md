# mojibake-fixer 设计文档

## 目标

AI 辅助编程写代码、注释、文档时，中文场景下偶发混入 ``（U+FFFD 替换字符）。`mojibake-fixer` 提供一次"扫描 → 修复"能力：

1. **默认覆盖 git diff 变更文件**（暂存 + 未暂存并集），开箱即用。
2. **支持指定文件/目录**，扩大扫描面。
3. **上下文推断修复**：结合前后中文语境推断 U+FFFD 原本字符，用 Edit 修复。
4. **克制不编造**：无法可靠推断的位置列出报告，交由用户决定。

## 形态选择：Command 而非 Skill

- 乱码修复是**动作型任务**：用户主动发起"扫描 → 修复"，命令式触发（`/mojibake-fixer`）最直接。
- 参数化天然匹配 command：默认 git diff、可选文件/目录，`/mojibake-fixer <path>` 直观传参。
- skill 的触发依赖 Claude 判断"当前场景是否该用"，成本高；修复乱码是显式动作，无此需求。
- 权衡：若未来其他模块要**自动**调用修复逻辑，skill 的嵌套引用更优雅。出现该需求时，可将"上下文推断规则"抽为共享片段供 skill 引用，command 保留手动执行入口。

## 修复策略：上下文推断

U+FFFD 是解码器遇到无效 UTF-8 字节序列时写入的替换字符，**原始字节已丢失**，无法像 GBK/UTF-8 编码错位那样字节级还原。唯一可行的"修复"是结合上下文推断原字符：

- 中文语境的 `` 前后通常有强语义线索（词、句、常见搭配），足以推断缺失内容。
- 设置**确定性门槛**：只有把握高才写入修复（用 Edit），存疑一律计入"无法推断"清单，守"不编造"原则。
- 修复后复查：再次 Grep 扫描范围，残留应只剩清单中的位置。

## 边界

| 场景 | 处理 |
| --- | --- |
| U+FFFD `` | 上下文推断修复；无法推断则报告 |
| GBK/UTF-8 编码错位（字节仍在，如 `锟斤拷`、`Ã©`） | 只报告位置，不自动转换（字节级，需重写文件） |
| 扫描范围外文件 | 不触碰 |
| 文件/行/整段增删 | 不做，仅字符级替换 |

## 与仓库其他模块的关系

- [commit-draft](../commit-draft/design.md)：保证 commit 输出不复述乱码（输出自检）；mojibake-fixer 事后修复源文件本身的乱码。两者互补。
- 未来若需自动联动（如 commit-draft 检测到乱码提示先跑 `/mojibake-fixer`），将推断规则抽为共享片段，保持单一来源。

## 变更理由

- **v0.1.0**：初始设计。AI 辅助编程中文场景 U+FFFD 乱码的修复工具，Command 形态 + 上下文推断策略。
