# session-review 设计文档

## 目标

AI 辅助编程会话结束后，产出技术复盘报告（根因分析、解决方案、关键改动），沉淀为可归档的 markdown：

1. **会话收尾即复盘**：任务完成后（尤其 bug 修复后）一键生成复盘报告，把"为什么这么做"从会话中沉淀下来。
2. **会话优先**：以会话上下文为事实来源——改动可能尚未实施，git diff 为空或不全，复盘不应被代码状态阻塞。
3. **可复制归档**：输出单个 `markdown` 代码块，直接复制即可粘贴为 .md 文件。

## 设计原则

- **会话上下文最高优先**：与 commit-draft（git 变更优先）恰好相反——复盘的是"决策过程"，即使未实施、未提交也要如实复盘；git diff 只作核对与补全。
- **diff 补全不覆盖**：会话中没提到的文件、或改动描述含糊时用 diff 补上；会话与 diff 冲突时以会话为准。
- **不编造**：根因、方案、改动必须来自会话或 diff 的真实信息；信息不足时如实标注"待确认"或省略章节，不臆测填充。
- **聚焦"为什么"**：报告偏重根因与方案取舍，不罗列代码细节。
- **无内容不硬生成**：会话与 diff 均无可复盘内容时，明确告知用户，不输出空报告。
- **语言跟随仓库**：默认中文。
- **输出前自检**：继承 commit-draft v0.1.2 的教训（Windows 下 GBK 编码文件被按 UTF-8 读取产生 U+FFFD 并被复述进输出），生成后检查乱码，发现则重写，确认干净才输出。

## 信息收集流程

```text
1. 会话上下文                # 任务/问题描述、根因分析、方案决策、改动说明、验证结果（最高优先，必做）
2. git diff --cached --name-status   # 暂存区变更（补全核对）
   为空 → git diff --name-status     # 全部变更
   都没有 → 跳过，不阻塞
3. 需要理解细节时，查看具体文件 diff 或读取文件内容
4. 命令参数中的链接/说明 → 背景来源引用
```

## 报告结构

```markdown
# 技术复盘：<主题>

## 背景            # 需求来源、问题现象、触发场景（来源链接追加一行 > 来源：）
## 根因分析        # 直接原因 + 深层原因，可含推理链条
## 解决方案        # 做了什么、为何选此方案、取舍
## 关键改动        # 文件 → 改动说明 表格
## 验证与结果      # 实测/测试/日志；未实施或未验证则如实标注
## 经验与后续      # 教训、可复用经验、遗留问题；无则省略
```

没有内容的章节整节省略，不输出空标题。

## 边界条件

- 改动未实施、git diff 为空：以会话为准照常生成，验证章节标注"未实施"。
- 会话与 diff 冲突：以会话为准。
- 会话/参数带需求或 bug 来源：背景末尾追加 `> 来源：<链接或编号>`，多个来源用 `、` 分隔；不自行杜撰来源。
- 会话与 diff 均无可复盘内容：告知用户"没有可复盘的内容"，不输出报告。
- 乱码：diff/文件内容为 GBK 编码时可能读到 U+FFFD，不复述乱码原文，改用 ASCII 或推断描述，重写并复检后输出。

## 变更理由

- **v0.1.0**：初始设计。基于 commit-draft 的使用模式（主动调用、单代码块输出、乱码自检）与逆向信息优先级（会话 > diff），落地 AI 辅助编程会话的技术复盘与根因归档。
