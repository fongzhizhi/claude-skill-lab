# Claude 会话状态看板：实现计划

> 目标：在 Windows 上做一个置顶、常驻的轻量看板，实时（或定时）展示所有 Claude Code 会话的状态，重点提示"询问中 / 已完成 / 已中断"的会话，避免多会话并行时卡在无人处理的状态。


## 一、背景与目标

### 问题

多个 Claude Code 会话在后台并行时，某个会话可能停在权限询问、等待输入、或已意外中断，但用户不知道，导致任务卡住。VSCode 插件本身有状态筛选，但不主动提醒，也不常驻可见。

### 目标

| 目标 | 说明 |
|------|------|
| **常驻可见** | 置顶窗口，贴在屏幕角落，不占 Alt-Tab |
| **状态聚合** | 一个窗口看到所有会话的状态 |
| **重点突出** | 需要用户处理的会话（询问中）排在最前、高亮 |
| **低开销** | 不调用 Claude API，不显著占用 CPU/内存 |
| **可扩展** | 后续可加入通知、点击跳转、历史记录 |

### 非目标（第一版不做）

- 跨机器聚合
- 会话内容预览
- 远程控制会话（批准/拒绝权限）
- 与 claude-skill-lab 的 lab 命令深度集成（可作为后续迭代）


## 二、状态定义

这是整个工具的核心。状态判定必须准确，否则看板会误导用户。

| 看板状态 | 判定依据 | 优先级 | 颜色建议 |
|---------|---------|--------|---------|
| **询问中（需处理）** | 会话处于等待用户输入/权限确认 | 最高 | 红 / 橙 |
| **进行中** | 会话正在运行（busy / working） | 中 | 绿 / 蓝 |
| **已完成** | 会话空闲，上一轮任务结束 | 低 | 灰 |
| **已中断 / 异常** | 进程已不存在，或长时间无状态更新 | 高 | 深红 / 黄 |
| **未知** | 无法解析状态文件 | 低 | 灰白 |

**判定优先级**：询问中 > 已中断 > 进行中 > 已完成 > 未知。

### 状态来源与判定逻辑

状态获取有两条路线，建议**第一版走路线 A（读取本地状态文件）**，路线 B（hooks 推送）作为后续增强。

#### 路线 A：读取 session 注册表（首选）

Claude Code 运行中的会话会在本地维护状态文件，路径大致为：

```
~/.claude/sessions/<pid>.json
```

状态字段的映射（具体字段名以实际文件为准，需在开发时抓取样本确认）：

| 文件中的状态 | 看板状态 |
|-------------|---------|
| `waiting` / `requires_action` | 询问中 |
| `busy` / `working` / `running` | 进行中 |
| `idle` | 已完成 |

**进程存活检测**（用于判定"已中断"）：
- 从文件名或文件内容中提取 PID
- 在 Windows 上检查 PID 是否存活
- 如果 PID 不存在，但状态文件仍存在 → 标记为"已中断"

**超时兜底**：
- 如果状态文件长时间（如 30 分钟）未更新，且进程仍存活 → 标记为"可能卡住"，单独提示
- 如果进程已不存在 → 直接标记"已中断"

#### 路线 B：hooks 推送（后续增强）

在 `~/.claude/settings.json` 中注册 hooks（`Notification`、`Stop`、`SessionEnd`），把事件推送到本地看板。实时性更好，但需要修改配置，且要处理 hook 脚本的跨平台问题。**第一版不做，作为 v2 的优化项。**


## 三、技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| **桌面框架** | **Tauri 2** | 安装包小（5MB 级别），内存占用低，支持置顶窗口，前端用 Web 技术开发效率高 |
| **前端** | 原生 HTML/CSS/JS 或轻量框架（如 Svelte） | 界面简单，不需要重框架 |
| **状态读取** | Node.js 脚本（Tauri 的 sidecar 或 Rust 端直接读文件） | 复用现有 JS 生态，读写 JSON 方便 |
| **进程检测** | Rust 端调用 Windows API，或 Node 执行 `tasklist` | 判断 PID 存活 |
| **打包** | Tauri 的 Windows 安装包（msi / exe） | 一键安装，无需用户配环境 |

**备选**：如果不想引入 Tauri 的 Rust 工具链，可以用 **Electron**，但体积和内存占用明显更大。考虑到"低开销"的目标，Tauri 更合适。

**最低可行替代**：如果 Tauri 的学习成本过高，第一版可以用 **Python + pywebview**（类似 ClaudeWatch 的思路）或 **纯 Node + 本地 HTML 页面 + 浏览器窗口置顶工具**。但长期看，Tauri 的体验最好。


## 四、架构设计

```
┌─────────────────────────────────────────┐
│           Tauri 置顶窗口（前端）          │
│  ┌───────────────────────────────────┐  │
│  │ 会话列表（按状态排序）              │  │
│  │  ├─ [红] 询问中  pro-ui  PRO-159.. │  │
│  │  ├─ [黄] 已中断  pro-pcb PRO-158.. │  │
│  │  ├─ [绿] 进行中  chameleon ...     │  │
│  │  └─ [灰] 已完成  ...               │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
              ↑ 定时轮询（2~5 秒）
┌─────────────────────────────────────────┐
│        状态采集器（Rust / Node）          │
│  1. 扫描 ~/.claude/sessions/*.json       │
│  2. 解析状态字段                          │
│  3. 检查 PID 存活                         │
│  4. 计算"最后更新时间"                     │
│  5. 输出结构化状态列表                     │
└─────────────────────────────────────────┘
```


## 五、核心逻辑：状态判定

采集器每次轮询执行以下步骤：

```
1. 列出 ~/.claude/sessions/ 下所有 *.json 文件
2. 对每个文件：
   a. 读取内容，解析状态字段（字段名需实测确认）
   b. 从文件名或内容提取 PID
   c. 检查 PID 是否存活
   d. 读取文件最后修改时间
3. 判定：
   - PID 不存在 → "已中断"
   - 状态 = waiting/requires_action → "询问中"
   - 状态 = busy/working → "进行中"
   - 状态 = idle → "已完成"
   - 解析失败 → "未知"
4. 按优先级排序（询问中 > 已中断 > 进行中 > 已完成 > 未知）
5. 输出列表给前端
```

**容错原则**：
- 单个文件解析失败不影响其他会话
- 状态字段名可能随 Claude Code 版本变化，解析失败时标记"未知"，不崩溃
- 如果 `~/.claude/sessions/` 目录不存在，显示"未检测到会话"，而不是报错


## 六、UI 设计

### 窗口形态

| 属性 | 设置 |
|------|------|
| 尺寸 | 约 320×400 px，可拖拽调整 |
| 位置 | 屏幕右侧，默认靠上，可拖拽 |
| 置顶 | 始终置顶（always on top） |
| 任务栏 | 不显示（skip taskbar） |
| 透明度 | 可选，默认 90% |
| 关闭行为 | 最小化到托盘，而不是退出 |

### 列表项

每行显示：

```
[状态色块] 会话标识（项目名 / 工单号）   [状态文字]  [最后更新时间]
```

示例：

```
🔴 询问中    pro-ui     PRO-159115    3 秒前
🟡 已中断    pro-pcb    PRO-158901    12 分钟前
🟢 进行中    chameleon  feat-4.1      1 分钟前
⚪ 已完成    pro-ui     fix-4.2        5 分钟前
```

### 交互

| 操作 | 行为 |
|------|------|
| 左键点击行 | 在 VSCode 中打开对应项目（如果可定位） |
| 悬停 | 显示完整路径、完整状态描述 |
| 右键 | 菜单：隐藏已完成、刷新、设置 |
| 拖拽 | 移动窗口位置 |

### 空状态

没有活跃会话时，显示"暂无活跃会话"，窗口可自动变暗，减少干扰。


## 七、开发计划

### 阶段一：MVP（1～2 天）

**目标**：能读状态、能显示、能定时刷新。

- [ ] 抓取 `~/.claude/sessions/` 下的真实文件样本，确认字段结构
- [ ] 写一个 Node 脚本，读取并解析状态，输出 JSON
- [ ] 用 Tauri 搭建最小窗口，置顶显示，前端轮询 Node 脚本的结果
- [ ] 实现状态排序和颜色区分
- [ ] 打包成 Windows 安装包

**验收标准**：开一个 Claude 会话，看板能在 5 秒内反映"进行中"；会话停在询问时，看板显示"询问中"。

### 阶段二：完善状态判定（1 天）

- [ ] 加入 PID 存活检测，识别"已中断"
- [ ] 加入最后更新时间，识别"可能卡住"
- [ ] 处理解析失败、目录不存在等异常
- [ ] 增加"隐藏已完成"的右键菜单

**验收标准**：手动杀掉一个 Claude 进程，看板能在下次轮询时标记"已中断"。

### 阶段三：体验优化（1～2 天）

- [ ] 点击行跳转 VSCode
- [ ] 托盘图标，关闭窗口不退出
- [ ] 刷新间隔可配置
- [ ] 窗口透明度和主题（亮/暗）可配置
- [ ] 状态变化时的视觉提示（如短暂闪烁）

### 阶段四（可选）：通知与集成

- [ ] 状态变为"询问中"时，弹出 Windows 通知或播放提示音
- [ ] 作为 `claude-skill-lab` 的一部分，提供 `lab sessions` 命令
- [ ] 或作为独立开源工具发布


## 八、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| `~/.claude/sessions/` 的文件结构不稳定 | 解析失败 | 做容错，解析失败标记"未知"；优先用状态字段，不依赖单一字段 |
| 官方明确说部分文件不是稳定接口 | 版本升级后失效 | 把解析逻辑做成可替换的适配层，版本变化时只需改一个文件 |
| 轮询频率过高导致 CPU 占用 | 影响开发 | 默认 5 秒，可配置；文件读取很轻，实际开销很小 |
| Tauri 的 Rust 工具链学习成本 | 开发变慢 | 第一版可先用 Node + 轻量窗口方案验证，再迁移到 Tauri |
| 多显示器 / 缩放导致窗口位置异常 | 体验差 | 记录窗口位置，启动时恢复；对异常位置做兜底 |
